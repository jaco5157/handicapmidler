# DanDomain CMS snippet manifest

Captured on 2026-10-01. This manifest covers all 34 files tracked under `static/` before restructuring.

No live DanDomain location or operational owner could be verified from repository evidence. Consequently, every file starts in **Review**. A filename that appears current is not proof that the content is live.

## Status rules

- **Active:** Confirmed to be in use. Record its live CMS location, owner, and verification date. It will move to `storefront/cms-snippets/active`.
- **Review:** Not yet confirmed. It will move to `storefront/cms-snippets/review` so it can be checked later.
- **Delete:** Confirmed unused or replaced. Record the reason or replacement. It will be deleted in a separate reviewed commit, not during the initial move.

To classify a file, change its **Status** cell to `Active`, `Review`, or `Delete` and complete any known details in the remaining columns. Files still marked `Review` will never be deleted automatically.

These classifications are applied during **Phase 4 (CMS quarantine)**, not Phase 2. Phase 2 only moves the storefront assets and production services. The common CMS review deadline is **2026-11-01**. Git history and tag `pre-restructure-2026-10-01` remain available for recovery.

## Verification procedure

For each file:

1. Locate the exact DanDomain page, layout, email, product template, or custom-script field.
2. Export/copy the current live value before making changes.
3. Compare live content with the repository file; do not rely on filenames.
4. Test the live location on an appropriate page and viewport.
5. Set the status to `Active`, `Review`, or `Delete`, and record any known CMS path, replacement, owner, and verification date.
6. During Phase 4, move `Active` files to `active` and `Review` files to `review`.
7. Delete `Delete` files only in a separate reviewed commit after the review deadline.
